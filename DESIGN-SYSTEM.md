# NearTask — Design System

## 1. Colors

- **Primary:** `#2563EB` — Blue for primary buttons, links, and important actions.
- **Secondary:** `#0F766E` — Teal for secondary actions and supporting elements.
- **Background:** `#F8FAFC` — Light background for the application.
- **Text:** `#111827` — Dark text for headings and body content.
- **Accent:** `#F59E0B` — Amber for highlights and important information.
- **Success:** `#16A34A` — Successful actions and accepted bookings.
- **Error:** `#DC2626` — Errors and rejected bookings.
- **Border:** `#E2E8F0` — Card borders and dividers.

## 2. Typography

- **Font family:** Inter, with a sans-serif fallback.
- **H1:** 32px, bold.
- **H2:** 24px, semibold.
- **H3:** 20px, semibold.
- **Body text:** 16px, regular.
- **Button text:** 14px, semibold.
- **Secondary text:** 14px, regular.

## 3. UI Components

- **Navbar:** Displays the NearTask logo and navigation links.
- **Button:** Reusable component for primary and secondary actions.
- **ServiceCard:** Displays service title, category, provider, price, and a link to details.
- **ProviderCard:** Displays provider name, skills, and service information.
- **SearchBar:** Allows users to search for services by keyword.
- **CategoryFilter:** Filters services by category.
- **Input:** Reusable form field for booking details.
- **BookingForm:** Collects task description, preferred date, and proposed price.
- **StatusBadge:** Displays Pending, Accepted, and Rejected booking statuses.
- **Modal:** Displays confirmation or additional information when required.
- **EmptyState:** Explains when no services or bookings are available.
- **LoadingState:** Provides feedback while content is loading.

## 4. Layout and Spacing

- Use consistent spacing between sections and components.
- Use rounded corners for cards, inputs, and buttons.
- Keep service cards visually consistent.
- Use a responsive layout for desktop and mobile screens.
- Maintain sufficient contrast between text and backgrounds.

## 5. UI Design Principles

- Keep navigation simple and easy to understand.
- Display service prices clearly.
- Make booking actions easy to identify.
- Use consistent status colors throughout the application.
- Avoid unnecessary screens and interactions in the MVP.
- Provide clear feedback when a booking is submitted, accepted, or rejected.

## 6. MVP Design Scope

The design system supports the NearTask MVP, including service browsing, search and filtering, provider profiles, booking requests, and booking status management.

Online payments, GPS tracking, and chat are outside the current MVP scope.
